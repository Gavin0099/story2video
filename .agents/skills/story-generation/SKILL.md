# 生成與審查原創海龜湯

先讀專案的 `PLAN.md` 與適用的 Issue。預設一次做一篇、一般觀眾、日常懸疑、45 秒，原創英文旁白搭配英文與可選繁中字幕。使用者有指定時依其需求。這是文字製作與審查流程，直接在目前工作階段完成，無需額外的模型服務。

## 生成

1. **先建立真相。** 選擇一個可觀察的反常現象，再確定誰做了什麼、何時發生、為何造成該現象。寫下事件順序、因果鏈、必要條件與固定事實。若故事成立必須依賴專業知識，先查證，並在題面交代觀眾需要知道的部分。
2. **逆向選線索。** 題面先給反常現象，再用兩三個可感知的線索逐步縮小解答範圍。逐條標記它支持的因果環節、排除的假設或只是背景。問一個明確問題。可讓觀眾自行形成錯誤假設，題面陳述須仍為真。讀取 [PTT 出題觀察](references/ptt-reading.md) 了解設計依據。
3. **準備盲解。** 另存僅含題面、依揭露順序排列的線索和問題的文字。檔名、標題、畫面及後設資料都避免洩漏答案。由未讀過真相的讀者或隔離工作階段提出最可能解、其他可能解、支撐線索與缺少的資訊。只有真的執行才填寫結果。作者自行找反例記為自審，盲解標記 `NOT_RUN`。答錯本身不構成退件，檢查答案與證據的關係。
4. **先審推理，再寫台詞。** 用下方硬性檢查找出最早的失敗原因。同一問題最多定向修兩次，仍卡住就換題或留待人工決定。每次修稿保存原版本與原因。
5. **製作單支影片的雙語草稿。** 英文先寫成可自然朗讀的短句，一個語意重點一拍。用 `hook → setup → clues → question → pause → reveal → explain` 切段。開頭約 3 秒內建立反常，中間留一個短停頓供猜題，最後說明答案如何解釋原線索。繁中採臺灣用語；保留資訊出現的順序、確定程度、否定、角色、數量和因果。逐段註記語氣、重音或停頓、畫面意圖和可見範圍。秒數只是規劃值，交給媒體階段以實際音訊校正。

## 審查

對每一項填 `PASS`、`FAIL` 或 `PENDING` 並附證據。優先處理阻擋項目，指出台詞／段落 ID、問題、具體反例與最小修正。資料不足時保留 `PENDING`。

| 硬性檢查 | 判定 |
| --- | --- |
| 因果與一致性 | 將每句題面對照真相及時間線。揭曉能解釋每個明顯異常；關鍵共同前提在揭曉前已有公平提示。 |
| 線索公平性 | 至少嘗試兩個符合常識的替代解。指出哪條已公開線索排除它們，或說明可接受的等義答案範圍。存在同樣吻合且核心機制不同的解釋時，補訊息、收窄問題或接受多解。 |
| 原創與權利 | 比對可取得的專案題目，優先比「反常現象 → 隱藏原因 → 解題線索」組合。記下檢查範圍、候選來源與權利審查狀態。有疑似近似或不明授權則送審。PTT 僅供出題方法分析。 |
| 雙語一致 | 兩種語言用相同線索能推出相同答案。遇到諧音、雙關、文化背景門檻或翻譯造成的額外提示，重做該線索並重審。 |
| 防劇透 | `reveal` 前逐一核對旁白、兩種字幕、分鏡、封面、標題和音效提示。把揭曉的答案獨立成段，標記字幕和畫面要等答案詞實際讀到才顯示，並將此點交給媒體 QA 驗證。 |
| 短片可讀性 | 一次朗讀能聽懂指涉和因果，每拍至多一個新重點。0–3 秒先給反常現象，保留思考和足夠的解釋時間，估計能落在 30–60 秒。標記技術量測尚未執行的項目。 |

用本次結果分別為邏輯、線索公平、反轉、原創、跨語言、視覺可呈現性評 0–5 分並附一句理由。0 表示有直接反證，3 表示基本成立但需修改，5 表示有具體證據且未見明顯缺陷。未知記 `PENDING`。六項齊全時，24/30 可作人工挑選候選的參考。硬性缺陷仍需修正，分數不代表可解性或市場驗證。

## 交付

- **內部故事稿**保留真相、時間線、因果、必要條件、公開線索與其功能、預期解、可接受的等義解、最強反例、權利、修訂版次與審查。已知才填模型、版本、成本與輸入／產出雜湊。
- **盲解題面**與內部稿分開交付。
- **雙語製作草稿**用相同的 segment ID 對應角色、英文旁白／字幕、繁中字幕、語氣、停頓與畫面指示，標記 `reveal_segment_id` 及尚待核查的 QA 項目。附審核結論 `REJECTED` 或 `REVIEW_REQUIRED`，列出進入製作前要解除的問題。
- 只有具備可追溯的人工作品批准及適用的版本化契約後才匯出正式 Episode。現有 M0 v1 限 `zh-TW`，因此英語主旁白草稿目前維持獨立交付，等待相容契約。製作、上傳與公開另走專案對應關卡。
