# Shorts Viewer Gate

這是 Story Quality Lab 的人工試片流程。文字 AutoLoop 保留三位獨立讀者皆達 90 分的門檻。成片驗收看觀眾第一次播放後能否自己解釋謎底，以及是否覺得反轉有趣。

## 出題到試片

| 時點 | 檢查 |
| --- | --- |
| 出題 | 用一句話問清楚反常事件，用一句話說出答案。列出觀眾合理的初始假設、能改變判斷的線索，以及最容易混淆的另一種解釋。 |
| 分鏡 | 在揭曉前安排具體可見或可聽的線索。為每條必要線索標記成片時間、載體及字幕對照。揭曉用動作或畫面讓觀眾看見因果。 |
| 技術 QA | 播放實際 MP4，核對聲音、字幕、必要線索和結尾。換剪輯或語言版本時各自保存影片 SHA-256。 |
| 真人首看 | 每一版收滿五位初次觀看者。以中性檔名交付 MP4，統一裝置類型、字幕語言、顯示狀態和音量環境。 |
| 公開後觀察 | 已獲另行授權發布的成片，於發布後第 7 和 28 天記錄 Shorts 動態曝光、Stayed to watch、Engaged views、平均觀看百分比，以及可取得的留存曲線。對照曝光量及片齡，缺項記為待取得。 [YouTube 指標說明](https://support.google.com/youtube/answer/12220281?hl=zh-Hant) · [YouTube 留存報表](https://support.google.com/youtube/answer/9314415?hl=zh-Hant) |

## 主持人操作

1. 觀眾為從未看過同一故事任何版本的真人。先確認是否熟悉該故事，再提供成片。主持人保存劇本、答案、先前分數、預設初始假設、片種和版本選擇理由。
2. 手機直式播放一次，將繁中字幕打開並在開始前確認可用。播放中不暫停、不倒帶、不補充提示。若播放器或字幕有故障，保留該次紀錄並以新觀眾補足。觀眾若主動停看，保留為有效樣本，理解及頓悟依原始回答判定。
3. 播完才依序發問，先收完答案，再問線索與感受。把原話記進[試片表](viewer-gate-record.csv)。使用匿名觀眾代碼，保留觀看順序、裝置、音軌、字幕狀態與實際檔案雜湊。

   1. 這支短片在問什麼？
   2. 你覺得事情為什麼會這樣？請用一句話說出來。
   3. 你記得哪個畫面、動作或聲音讓你這樣想？有哪裡跟不上？
   4. 揭曉有沒有改變你一開始的想法？這個反轉對你來說有趣、普通，還是無感？為什麼？

4. 收答案前先依該集主持人題卡固定「回答到哪個因果才算對」。同義表述可以算對，僅說出道具、結果或人物心情則逐條對照核心。題目重述與線索回憶供診斷。頓悟須有觀眾明確表示有趣，並說出自己理解改變之處。一開始就猜中的觀眾也可指出揭曉提供的新理解。

| 結果 | 判定 |
| --- | --- |
| 待驗 | 同一 MP4 版本的有效真人樣本少於五筆。 |
| 通過 | 五人中至少四人說對核心答案，且至少三人明確覺得反轉有趣並能說明理解改變之處。 |
| 未通過 | 有效樣本齊全，但其中一道門檻未達標。依原始回答找出漏掉的線索或反轉問題。修改成片後，以新版本和未接觸過故事的觀眾再驗。 |

每支影片以同一版本開始時分派的五份有效樣本判定。已曝光、重播、收到提示或播放器故障的場次留存但排除，原因寫入記錄。真人首次理解的結論以原始回答支撐。五人的門檻是本次探索設定。

試片表每位觀眾每個版本填一列。判定欄使用 `yes` 或 `no`。排除的場次在 `valid` 填 `no`，寫明原因，三個判定欄留空。記錄原話後才填判定。

## 三支試作的控制條件

三支採用同一套敘事順序與視聽樣式。前三秒先交代異常事件，接著顯示線索，給一個思考節拍，再用看得清楚的動作解答。都以 9:16、1080×1920、30 FPS、35–45 秒為目標，使用英文旁白與已開啟的繁中字幕。各集片長按實際配音安排。播放測試版可將同一份繁中字幕燒錄，讓測試者看到一致的字體、位置與顯示時機。正式上架版本保留可切換的英語與繁中字幕。

可讓相同的五人測三支不同故事，逐人輪替播放順序。每位觀眾對同一故事只看一版。這輪是一種類型一支，結果只能指出哪支成片較清楚，還需要同類型的其他作品才能外推。

需要比較配音時，從一則故事另外做中文旁白版。保存相同畫面、剪輯、繁中字幕和播放環境，配音長度以相同段落終點對齊。把初次接觸者分派到英文或中文旁白組，分開記各組的原始回覆和分母。
